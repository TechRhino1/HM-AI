## THE ACTUAL ROOT CAUSE — two concrete bugs (supersedes the §above "EXECUTION PATH" claim)

The earlier "simulator models only pure SL/TP-with-slippage" / "missing exit policy + cooldown"
theory was **WRONG**. `trade_simulator.py:55,270,353` already imports and calls `evaluate_exit` +
`geom.to_policy` — BE/partial/trail ARE modelled. The real bugs are two specific defects, found via
`tools/diag_engine_vs_sim.py` (engine vs sim on same H1_95d + profile):

**Bug A (MASTER) — off-by-one phantom target hits in `trade_simulator.simulate_trade`.**
`signal_scan` fills at the NEXT bar's open, so the trade is live at `entry_idx+1`, but the loop
started at `entry_idx` (the signal bar) and tested it for SL/TP. For tight `tp_r` the signal bar
frequently hits target before entry → phantom TPs the engine can never take. Inflated sim WR.
- Proof (NAS100, before): sim WR **87.66%** vs engine **65.91%**; walk Jaccard **0.131**; sim TP 135 vs engine 42.
- **Fix A applied** (`trade_simulator.py`): `entry_time = bars.time[entry_idx+1]` /
  `for j in range(entry_idx+1, n):`. After: sim WR **76.27%** ≈ engine **76.60%**; Jaccard **0.48**;
  exp engine −0.0374R vs sim −0.0396R (agree to 0.002R). Compiled clean.

**Bug B — engine applied UNVALIDATED per-regime geometries.** `engine.py` used
`wr_profile.geometry_for(regime_name)` (e.g. NAS100 TREND_BULL `tp_r=1.5` vs base `0.25`), geometries
the calibrator never measured as an ensemble. OOS is measured on the validated BASE geometry.
- **Fix B applied** (`engine.py:512`): `geom = wr_profile.geometry`. Verified engine NAS100 WR now
  **76.60%** = the earlier `--probe` base-geometry run (per-regime override no longer applied).

**Why this IS the faithful "calibrate on engine backtest":** Fix A makes the sim count only real
post-entry bars; Fix B makes the engine use the validated geometry. OOS ≈ engine per-trade edge by
construction — no infeasible per-geometry engine call needed. The big refactor is NOT required.

## Per-symbol root-cause analysis + optimization attempts (2026-09-11)

### THE CENTRAL ROOT CAUSE (quantified)
Portfolio **payoff ratio = 0.279** (avg win **0.2765R** vs avg loss **−0.9917R**) ⇒
**breakeven win rate = 1/(1+0.279) = 78.2%**, but the system delivers **75.31%**.
It is structurally BELOW breakeven — that single identity explains the negative portfolio.

Why payoff is so poor: the calibrator's objective is `target_wr=0.75`. It chases win rate, so it
selects tiny `tp_r` (0.25–0.40) — `tp_r=0.25` was chosen for **13 of 16 symbols**. Tiny tp_r ⇒ tiny
payoff ⇒ breakeven WR 76.9–80% ⇒ zero margin. Measured margins (WR − breakeven WR):
AUDUSD −2.15, NZDUSD −4.22, NAS100 +0.65, XAUUSD +0.46, USDJPY +7.34 (but engine −0.178).
`_rank_key` (winrate_targeting.py) is the culprit: Tier 1 (target missed, positive exp) and Tier 0
rank by **WIN RATE**, and the target is missed far more often than met.

Tooling: **`tools/sweep_tp_r.py`** (new) sweeps tp_r per symbol and prints WR / realised payoff /
breakeven WR / **margin** / expectancy / PF / exit-reason mix, plus what each objective would pick.
Output: `reports/sweep_tp_r.txt`. Re-run this for any future tp_r question.

### Optimization attempts: BOTH MADE IT WORSE (reverted)
| variant | expectancy | PF | net |
|---|---:|---:|---:|
| baseline (WR-chasing) | **−0.037R** | **0.93** | **−$400** |
| expectancy-max + margin guard | −0.089R | 0.84 | −$692 |
| t-statistic of expectancy | −0.065R | 0.82 | −$1063 |

**Why they failed (the real lesson):** the objective is NOT the binding constraint. The
**walk-forward OOS does not predict the engine** — measured OOS→engine gaps of **−0.19R to −0.26R**:
ETHUSD +0.053→**−0.202**, USDCAD +0.013→**−0.175**, UK100 +0.042→**−0.147**, NAS100 +0.001→−0.035.
Only GER40 matched exactly (+0.130→+0.130). Optimising harder against an unfaithful instrument just
selects more precisely for the instrument's bias.
Also: in-sample expectancy is a **winner's curse** (XAUUSD in-sample +0.101R → OOS −0.123R).
And `tp_r=2.0` is a trap — it holds trades into the BE/trail region (trail_activation_r=2.0) where
sim and engine diverge violently (NAS100: OOS 44.2% WR vs engine **23.3%**). Grid capped back at 1.5.

### Preserved in code (currently unused by selection, documented)

### Conclusion
No robust positive-expectancy portfolio exists on this 95-day dataset. **Live trading stays OFF.**
The one remaining high-value fix is the engine-backed calibrator (measure OOS with `BacktestEngine`,
which is what makes OOS faithful) — that is the prerequisite for any objective tuning to help.

## Reproducibility fix — backtests were mutating live state (2026-09-11)

**Symptom:** two identical-code runs gave different results (−0.037R/−$400 vs −0.063R/−$1,095) and
different trade counts (NAS100 107 vs 118, XAUUSD 84 vs 97). A/B testing was therefore meaningless
for differences under ~0.03R / ~$700.

**Cause:** `offline_mode()` sets a global flag, but several persistence layers never checked it, so a
backtest wrote learned state that the NEXT run then loaded:
- `jarvis/learning/strategy_bandit.py` — **no guard at all**. `record_outcome()` → `_save_state_internal()`
  wrote on every trade. Reached from the engine via `decision_engine:71` → `strategy_selector:33`.
  Also its `state_file` default was **CWD-relative** (state depended on launch directory).
- `jarvis/risk/circuit_breaker.py` — no guard; a tripped breaker / symbol-regime pauses persisted, so
  the next run started already tripped and took fewer trades (explains the count differences).
- `jarvis/risk/drawdown.py` — no guard; leftover daily_start_equity/peak_equity could trip the
  daily-loss cap early on the next run.
- `jarvis/learning/online_ml_predictor.py` — already guarded (is_offline=4) ✓.
- `trade_memory.py` / history DB — no guard but only used by `orchestrator.py`, not the backtest path.

**Fix applied:**
- `strategy_bandit.py`: `state_file` anchored via `resolve_db_path()`; `_save_state_internal()` and
  `_load_state()` both return early under `is_offline()`. In-memory adaptation still occurs during a
  run (causal + deterministic), but each backtest starts from the same priors and persists nothing.
- `circuit_breaker.py` / `drawdown.py`: under `is_offline()` set `db_path = ""`, the documented
  in-memory sentinel both classes already honour via `if self.db_path:` checks.

**Verified (partial):** after the fix, the state files are no longer rewritten by backtests
(bandit / online-ML / circuit DB mtimes unchanged across two runs), and most symbols reproduce
exactly. **But NOT fully deterministic yet** — USDJPY 53 vs 63 trades and XAUUSD 97 vs 84 still
differ between runs.

**Remaining cause — wall-clock time in the backtest path (`time.time()`):**
- `jarvis/risk/circuit_breaker.py:98,128,134,138,165` — symbol/regime pauses are
  `now + 2700s` / `now + 3600s` and are tested with `time.time()`. In a backtest the bars are
  historical, so a 45-minute pause is evaluated against REAL seconds of CPU time. Whether it has
  expired depends on machine speed, not market time.
- `jarvis/risk/risk_engine.py:70,88` + `_prune_expired_reservations` — risk reservations use a
  15 s real-time TTL; whether a reservation is still counted toward portfolio heat depends on
  wall-clock, which can change whether a trade is authorised.
- Note `RiskEngine.__init__` already passes `db_path=""` when `is_backtest=True`, so the circuit
  breaker was NOT persisting in backtests — the persistence fix matters for other callers, but the
  residual variance is the clock, not the disk.

**Fix implemented — clock injection:** `CircuitBreaker` gained `set_clock()` (default `time.time`) and
all its `time.time()` calls now use `self._now()`; `RiskEngine` gained `set_clock()` forwarding to the
breaker and setting its own `self._now` for the reservation TTL; `BacktestEngine` sets the clock to the
current bar's epoch seconds every bar (existing `bar_time`). Live is unchanged (no caller sets a clock).

**VERIFIED FIXED:** two consecutive backtests on identical inputs now give **identical results**
(`reports/final_confirm.log` vs `final_confirm2.log`, timings normalised). Stable figure for the shipped
code: **529 trades | WR 73.3% | −0.063R | PF 0.83 | −$1,095.04 | DD 12.01%**.
(An earlier pair, `repro2_run1/2`, reported −0.057R/−$840.73 but was taken BEFORE the init bug below.)
Previously the same code reported anywhere between −0.037R/−$400 and −0.063R/−$1,095.
A/B testing is now trustworthy — differences are real effects, not drift.

**Self-inflicted defect caught by tests:** my first `set_clock` was inserted at 4-space indent inside
`RiskEngine.__init__`, which terminated `__init__` early; the remaining initialisers became part of
`set_clock`'s body, so `_reserved_risk`/`_reserved_lock` were re-created every bar (and missing until the
first `set_clock`). 12 failures in `test_risk_engine_j3.py` / `test_adaptive_same_symbol_risk.py`
(`AttributeError: '_reserved_lock'`). Fixed by moving `set_clock` after `__init__`. **62 tests pass.**
Lesson: when inserting a method into a class via Edit, check the indentation terminates correctly and
re-run the unit tests — `py_compile` alone will NOT catch this class of bug.

**Rule for future work:** any new persistence layer must check `is_offline()` on BOTH load and save and
anchor via `resolve_db_path()`; any new time-based gate in the risk path must use an injectable clock,
never `time.time()` directly, or backtests become machine-speed dependent.
