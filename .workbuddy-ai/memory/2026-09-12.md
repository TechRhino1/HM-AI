## Engine integration of exit geometry — attempted then REVERTED (important)

Tried wiring the geometry into `BacktestEngine`. Rolled back with
`git checkout -- jarvis/backtesting/engine.py` (62 tests pass afterwards). Two defects:

1. **Runner hard cap negates the ladders.** Harness built B/C/D via
   `EXIT_GEOMETRIES(tp_r=1.0)` so the RUNNER got a 1.0R hard target → trades close the runner at
   1.0R BEFORE the 1.5R/2.5R rungs fire ⇒ B/C/D silently collapse to mode A. Ladder runners need
   `tp_r=None` (trail carries them), not 1.0.
2. **Mode A double-closes.** Mode A's schedule is a single 100% leg at tp_r; the new rung loop
   closes it AND the existing TP check closes it again → double-counted P&L. Only build rungs for
   schedules that contain a runner.

KEPT (additive, default to today's behaviour): `build_exit_geometry()` in
`jarvis/backtesting/exit_geometry.py`; `geometry_mode: str = "A_fixed_tp"` field on `WRTargetProfile`
(auto-serialised via `asdict`; `from_dict` filters to dataclass fields so old profiles load fine).

Remaining, in order: (1) build B/C/D with runner tp_r=None + rungs only when a runner exists;
(2) add an engine-vs-harness PARITY regression test (its absence is why both defects got through);
(3) persist geometry_mode through `calibrate_winrate.py`; (4) re-run `run_3month_backtest.py` and
confirm the engine reproduces the +0.1905R / PF 1.39 harness portfolio.
Only after (4) may those numbers be treated as live expectations.

**Lesson: do not ship partially-wired execution changes to a safety-critical trading engine —

## DEFINITIVE answer to "why is it not profitable" (2026-09-12)

Measured on the reproducible engine backtest (`reports/backtest_3month_report.json`):

    avg_win_R = 0.2776   avg_loss_R = -1.0018   payoff = 0.2771
    breakeven WR = 1/(1+payoff) = 78.30%      achieved WR = 73.35%
    MARGIN = -4.95 win-rate points

**The system is ~5 win-rate points below breakeven on every symbol.** It is NOT an entry problem —
73% directional accuracy is genuine skill. It is an EXIT/PAYOFF problem: winners are banked at
~0.28R while losers run the full -1.00R.

Two mechanisms, both quantified:
1. The win-rate-chasing calibrator sets tiny tp_r (0.25-0.4), capping winners BY CONSTRUCTION.
2. Even where tp_r is larger, realised avg win is far BELOW tp_r — UK100 tp_r=1.0 realised 0.536R,
   USDJPY tp_r=0.6 realised ~0.18R — because breakeven lock + trail + time stops cut winners early.

Per-symbol margin (WR − breakeven WR): AUDUSD -2.67 · NAS100 -3.2 · NZDUSD -3.8 · XAUUSD -0.6 ·
UK100 +20 but exp -0.147 · USDJPY +3.5 but exp -0.253 (both: realised payoff far below tp_r).

**The 5.1 harness proved the fix:** with ladder/ATR-trail geometries and NO breakeven, the same
entries produce +0.1905R / PF 1.39 at only 45% WR. So profitability is gated on exit geometry,
not on entry quality and NOT on paper-vs-live mode (the -4.95 margin is pure arithmetic and is
identical in any execution mode).

Architecture: TWO implementations of the same concepts.
- `market_structure.py:82-121` (OB/FVG, lookback 15/20, **NO mitigation flag**) → StructureContext →
  **dynamic_levels.py SL/TP**.
- `fair_value_gap.py` (OB/FVG + OTE + confluence, lookback 30/50, **HAS mitigation**) →
  decision_engine:858 + master_confluence:138 → **scoring only**.

**B1 (HIGH): SL/TP anchor to zones with no mitigation tracking.** Variant A carries no `mitigated`
key, so stops/targets can sit on already-consumed FVGs/OBs. The engine that tracks mitigation is only

**B2 (HIGH): stops placed AT liquidity.** `dynamic_levels.py:148-149,264-265` add raw
sell_side/buy_side_liquidity as SL anchors — but pools exist to be swept, so the stop dies on the
move being traded. Fix: when sweep_detected, anchor beyond `sweep_level ± max(sweep_magnitude,0.5)*atr`.
B3 mitigation = wick touch not trade-through (fair_value_gap:68,80,107,113).
B4 OB has no BOS confirmation. B5 confluence ignores direction (bullish FVG + bearish OB = "confluence").
B6 fallback fabricates BSL/SSL as price ± 2*ATR (dynamic_levels:526-527) — synthetic, set to 0.0 instead.
B7 "Unmitigated" asserted with no flag. B8 `==` float pivot compare. B9 inconsistent lookbacks.
B10 demand/supply zone = fixed 0.3% band above the swing low, not ATR-scaled.

CORRECT: liquidity.py:133-134 BSL=recent swing high / SSL=recent swing low; liquidity.py:105-118 sweep
requires break + close back + bullish close + 45% displacement + volume ≥40% + 0.15–3.5 ATR penetration;
FVG 3-candle rule identical in both engines; BOS/CHoCH standard.

## Master-trader signal/decision engine (commit 9b15c11)

New `jarvis/intelligence/signal_engine.py` — weighted, explainable, regime-adaptive decisions.
- `Signal` (value −1..1, confidence, weight, stale, reason); `SignalSource` base class → new data
  sources are pluggable (append to `register_default_sources()`).
- 7 built-in sources: structure, liquidity, momentum, volatility, fvg_ob, sentiment, ml — all
  tolerate absence; a missing *required* source sets `stale=True`.
- `REGIME_WEIGHTS` swap weights by regime (liquidity 1.30 in LIQUIDITY_SWEEP, 0.60 in TREND_*;
  momentum 0.90 in trends, 0.35 in COMPRESSION/RANGE). Unlisted keys fall back to DEFAULT_WEIGHTS.
- Outputs action / entry zone / SL / TP / size_pct / confidence + full per-signal contribution list
  (`decision.explain()`).
- Risk gates: max_risk_pct 0.5, max exposure 3%, max DD 10%, min confidence 0.55, min |score| 0.18.
- **Fails closed**: stale required source, structure-vs-liquidity conflict, low conviction, exposure,
  drawdown, or a non-computable stop → HOLD with a reason. Never guesses. Absent sentiment is
  treated as UNKNOWN, not neutral.
- `DecisionLogger` writes append-only JSONL to `data/decisions/decisions_YYYYMMDD.jsonl`.
- Smoke-tested: bullish sweep case → BUY conf 0.63 with liquidity +0.99 top contributor;
  missing structure → HOLD "missing/stale data"; flat market → HOLD conf 0.07.

**SMC B1/B2 fixed** (from the audit): market_structure FVG/OB now carry `mitigated` (trade-through
not wick-touch) and dynamic_levels filters them out of SL/TP anchoring (5 sites). Stops no longer
anchor AT liquidity — when a sweep is present the stop goes beyond `sweep_level ±
max(sweep_magnitude,0.5)*ATR`. 62 tests pass.
