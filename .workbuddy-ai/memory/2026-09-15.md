## The push hung, exactly as the skill predicts

`git push` on this machine does not fail — it **stalls silently**. The diagnostic signature matched
the `diagnose-git-push-auth` skill precisely:

| Probe | Result | Reading |
|---|---|---|
| `git ls-remote --heads origin` | exit 0 | Network fine; the problem is auth on the write path |
| `git config --get-all credential.helper` | `helper-selector`, then GCM | The known blocker is first in the chain |
| `git credential fill` | **exit 124 (hung)** | The selector is stuck — the decisive signal |

The fix from the skill worked on the first attempt, with no prompt and no user involvement:

```bash
GCM="C:/Users/Itrai/.workbuddy-ai/binaries/PortableGit/versions/1.2.0/mingw64/bin/git-credential-manager.exe"
timeout 180 git -c credential.helper= -c credential.helper="!$GCM" push origin main
```

`credential.helper=` (empty) resets the accumulated list so the effective chain becomes `[!GCM]` and
`helper-selector` never runs. **A plain `git push` had never once succeeded on this machine**; this
is the reliable path.

## Nuance worth remembering

Setting upstream tracking does **not** fix the hang. It only removes the need to name the remote and
branch. The selector is still in the chain, so a bare `git push` still stalls at rc=124 — the
bypass remains mandatory. This was added to the skill, along with the confirmed-working recipe and
the note that read operations (`ls-remote`, `fetch`) are unaffected.

# Session 2 — end-to-end audit, advanced terminal, regime-conditioned optimisation

Four-part request: audit every logic path, find interface/UI issues, redesign the UI on an advanced

## Regime-conditioned profit optimiser (new)

`jarvis/backtesting/regime_optimizer.py` + `tools/optimise_regime.py` + 34 tests.

The gap it closes: `optimizer.py` returns **one** geometry per trading mode, averaged over whatever
conditions the window contained. The win-rate calibrator (`intelligence/winrate_targeting.py`)
already had regime conditioning; the *profit* optimiser had none.

What made it cheap: `TradeOutcome` **already carries `regime`** (populated from the candidates
parquet, which carries a real `regime` column — 6 labels, not placeholders), and `select_sequential`
**already accepts a `regimes=` filter**. Both existed and were simply never used by the optimiser.
Conditioning is therefore free — `_outcomes` caches on the geometry alone, so one geometry scored
under six regimes costs one simulation plus cheap filtering passes.

Design points worth not relearning:

* **Selectivity must be regime-local.** `min_score` is a quantile of the symbol's own scores. The
  scores in COMPRESSION are not the scores in TREND_BULL, so resolving the quantile pooled and then
  filtering by regime silently rescales the selectivity. `SeriesBundle.min_score_for(q, regimes)`.
* **One blocking walk across regimes.** The engine holds one position per symbol whatever the
  regime. Selecting each regime independently books overlapping trades it can never take, and the
  phantom overlap clusters at regime turns — where the P&L is. Merge, then one `select_sequential`.
* **Order of decisions matters.** Search → deploy only on a measured win → *then* decide
  enable/disable from the geometry actually deployed. I got this backwards first and it disabled a
  regime whose own geometry was profitable, because the *pooled* geometry loses there.
* **`max_evaluations` is a budget per SEARCH.** It was an absolute counter, so with a low budget the
  first mode consumed it and later modes returned the unsearched seed geometry while reporting a full
  result. `tools/verify_ui_live.py` passes `max_evaluations: 12`, so it hit this on every run.
  Fixed with `_budget_start` / `_reset_budget()`.

**Measured result — all three modes (2026-09).** Two runs: SWING over all 20 symbols at
`--passes 3`, then all three modes over 8 liquid symbols at `--passes 1`. Smaller universe is less
converged but the direction is identical.

| Mode | Baseline OOS total R | Policy OOS total R | Trades | Verdict |
|---|---|---|---|---|
| SWING (20 sym) | −122.9 | −6.4 | 816 → 20 | improves total R |
| SWING (8 sym) | −12.9 | −1.6 | 342 → 105 | improves both |
| DAY_TRADING | −127.9 | −21.8 | 1220 → 262 | improves both |
| SCALP | −313.4 | **0.0** | 1419 → **0** | takes no trades |

The pooled optimum is not profitable in any mode. The policy's value is **loss avoidance, not
profit generation**. SCALP is the clearest case: all seven conditions clearly negative AND every
regime-specific geometry fails the constraints, so the answer is zero trades — eliminating a
−313 R loss outright. This independently reproduces the mode-reliability ordering from
`mode_aggregator` (SWING 0.346 > SCALP 0.1287 > DAY_TRADING 0.1064, all below neutral) by a
different method. Cache hit rate 90.6 %, which is the evidence the "conditioning is free" design
holds in practice.

Threshold duplication is deliberate: the disable gates (`0.05`, `12`) mirror
`winrate_targeting.regime_edge_table`, re-implemented rather than imported because
`intelligence` already imports `backtesting` and §2 requires the direction to be downward.
`test_gates_match_winrate_targeting` fails if they drift.

## The OILCash# bug — sizing out by 1000×

`resolve()` gave oil the **generic FX spec**: `contract_size` 100000 instead of 100, `pip_size`
0.0001 instead of 0.01, `max_spread_pips` 5.0 instead of 25.0, `asset_class` FOREX instead of
COMMODITY, digits 5 instead of 2. Position sizing out by 1000×, spread gating by 100×.

Cause: every other cash CFD had its broker `XxxCash#` alias (`US500Cash#`, `GER40Cash#`,
`UK100Cash#`…) — oil was the only omission, and `OILCASH#` contains no canonical name so the fuzzy
pass could not rescue it either. Fixed by adding `OILCash#` / `USOILCash#` → `WTI`.

Why the existing test missed it: `test_registry_matches_broker_manifest` resolves the **canonical**
name (`WTI`), which is always a registry key. The engine passes the **broker** name. New test
`test_broker_symbol_resolves_like_its_canonical_name` resolves `broker_symbol` against `symbol` for
every manifest — verified to fail with the alias removed.
