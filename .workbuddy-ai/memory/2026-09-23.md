## Traps confirmed this window

* **A bulk `git rm` triggered the vanish incident.** Deleting 16 root files + 7 configs
  made the entire `config/` directory disappear from disk mid-command (`ls: cannot access
  'config/'`). Recovered with `git checkout -- config/` — the index restore correctly kept
  the staged variant deletions. **The trigger here was a bulk `git rm`, not `git stash`.**
* **Phase 1 deletions were silently lost once** before this. The prior window reported them
  done; they were all still `PRESENT` and tracked. Always re-verify a deletion with
  `[ -f "$f" ]` — a "done" report from a sub-agent is not evidence.
* **`git rm -rf --cached <dir>` + `rm -rf <dir>` on an archive copy is a trap.** Phase 1
  had *copied* the junk configs into `config/archive/` instead of moving them, so
  `git add -A` staged 23,446 lines of byte-identical duplicates. Check `git diff --cached
  --numstat` before committing — a cleanup commit that adds 23k lines is a cleanup that
  failed.
* **A 404 on a new endpoint usually means a stale server, not a broken route.** `/health`
  returned a 404 HTML error page because the dashboard on 8501 was started *before* the
  edit and Python has no hot-reload. Don't debug the route; restart the process. To verify
  **without killing the user's running dashboard**, boot a second instance in-process on a
  spare port, probe it, and `srv.shutdown()` — see `.scratch/verify_health.py`.
* **`pytest.ini` has `testpaths = tests`**, so root-level `test_*.py` scripts were never
  collected — deleting them cannot move the suite count. Check this before worrying that
  removing test-named files breaks the baseline.
* **Never commit with `--no-verify`** (habit from other repos). This repo has no active
  hooks (only `.sample` files), so nothing was lost, but the flag was wrong.

## ⚠ The audit's headline root cause was WRONG — both entry models measured out

Two research agents ran the backtests that gate Phases 5 and 7. Both came back negative, and the
stop-floor one **overturned my own report's headline**.

* **"Median stop 0.21×ATR" does not reproduce.** Measured on 46,939 candidates: median candidate
  stop is **2.58×ATR (H1)**; only 0.2–3% sit below 1.11×ATR. Origin of the bad figure: a
  **daily-vs-H1 ATR unit error** — `symbol_registry.py:22` documents `typical_atr_pct` as *daily*
  ATR %, but `dynamic_levels.py:142` divides it into the *H1* `vol.atr`, so `atr_ratio` pins at its
  0.33 clamp on **69.8% of bars (FX 90–99.6%)**. The "volatility-adaptive buffer" is a constant.
  Consequence: **raising the stop floor is a measured no-op** (ΔE[R] = +0.00092; arms
  0.10/0.30/0.50 come out bit-identical). Knee ≈0.70×ATR and we are already past it.
* **FVG standalone: DO NOT PROCEED.** 0/20 pass DSR; Sharpe **negative on all 20**; win rates
  12–34.7% vs 42–59% needed at 1.5R. Loses less than always-long, which is not an edge.
* **"327 independent bets" is wrong** — internal proof: one symbol alone measures 3,971. Real
  ratio **4.2%, not 0.3%**. `deflated_sharpe_report.py:239` passes raw span entries to
  `effective_sample_size`, which wants `List[Dict]` trade records. Direction: effective n is
  *larger*, so the DSR bar is *less* severe than I reported — conclusion unchanged, severity was wrong.

**Rule: a ratio whose numerator and denominator come from different timeframes is not a
measurement.** Check the unit before quoting a multiple of ATR. And **a stop floor that changes
nothing across a 10× range is not the binding constraint** — prove a knob binds before tuning it.

## Baselines / traps

* **Never measure a baseline while another process is still writing test files.** My "3062" was
  taken mid-write and undercounted by ~13; the real figure was 3075+. Verify counts from the
  **junit XML**, not the stdout summary (the harness truncates it).
* **`git add -A` while a teammate is mid-task sweeps up their in-flight work.** It happened here —
  a report-only commit swallowed `database.py`, `server.py`, `orchestrator.py` and a new test file.
  Scope the add (`git add <paths>`), or check `git diff --cached --stat` before committing.
* **A safe-delete hook can block a pytest run** when a turn accumulates bulk deletions (agents
  writing/removing backtest temp files hit a 4667/50 threshold). Don't retry; read the junit XML.

## Two defects my own Phase 2 work shipped (fixed in 523f47e)

Caught only by the regression tests written for it — neither was visible by reading.

* **`/health` answered "ok" about subsystems it never probed.** `_send_health` stores a probe
  exception as `{"error": ...}`, then reads the verdict with `.get("held")` / `.get("wedged")`.
  Those keys are absent from an error dict, so both read as healthy and the endpoint returned
  200/"ok" while having probed nothing. General rule: **a probe that returns an error dict must
  not be read with `.get()` for a verdict key — absence of a key is not a healthy reading.**
* **A revoked token outlived its own expiry** — membership was tested before the sweep ran.
  General rule: **sweep before you test membership**, or the stale entry wins one last time.
