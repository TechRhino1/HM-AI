# 2026-09-22 — iOS redesign (phone + tablet) shipped; 2 pre-existing Python failures

## iOS redesign — committed (pending push)

Phone ≤599px + tablet 600-1024px redesigned per Apple's HIG; desktop ≥1025px
deliberately untouched. Single deliverable: a real iOS app feel on the phone,
a sidebar+split-view on the tablet, and the existing desktop terminal kept
byte-identical for the nav strip.

### Breakpoints

* ≤599px nav bar (drawer/brand/session, account strip, large title) + bottom
  UITabBar + modal bottom sheets. The tab bar is reparented onto `<body>`
  because `.tt-rail`'s `backdrop-filter` would otherwise make it the
  containing block and pin it under the nav bar.
* 600-1024px 236pt sidebar (rose-to-vertical nav) + split view on the right.
  The same `.tt-tab` DOM as the phone tab bar becomes the sidebar nav, so
  one state machine and no duplicated destinations.
* ≥1025px unchanged.

### Defects caught + how

1. Phone news body squashed to 24px (tallest control 37px). Root: a flex
   child with `min-height:0` inside a panel whose head is 132px. Fix:
   `.tt-panel__body { min-height: 96px }` on phones.
2. Tablet chart seg 231→184. Root: my 44pt + 1rem rule widened the
   buttons past the panel head's width. Fix: `.tt-seg { flex:1 1 100% }`
   (own line) + `.tt-seg__btn { flex:1 1 0; padding:0 4px; font-size:0.75rem }`.
3. Tablet positions tab count badge overflowed. Root: equalising
   `.tt-pos-tab` (`flex:1 1 0`) shrank it to 6px while a 22px badge had
   to stay. Fix: `.tt-pos-tab { flex:0 1 auto }`, content-sized.
4. News LIVE chip overflowed by 18px. Root: `.tt-chip` is `white-space:
   nowrap` and the long `LIVE · EUR CPI …` text is wider than the panel.
   Fix: `.tt-chip { white-space: normal; overflow-wrap: anywhere }` on
   ≤1024.
6. Icons leaking onto desks. Use `.tt-tab__ico { display: none }` outside
   media; show only in the ≤1024 blocks. Avoids the 300x150 SVG default.

## pre-existing Python failures (now fixed)

`tests/test_execution_mode_is_recorded.py::TestTheModeCanBeFiltered::test_a_possible_filter_still_queries`
`tests/test_execution_mode_is_recorded.py::TestTheModeCanBeFiltered::test_mode_and_origin_compose`

Root: `fetch_recent_trades` calls `sync_mt5_history` on every read, which
INSERTs real broker deals into whatever DB the caller hands it. A test
fixture that builds `SQLiteTradeDB(db_path=str(tmp_path/"hist.db"))` would
receive real broker tickets (940451636 and friends) the first time it reads.
The file does not test sync semantics, so the fixture now stubs
`sync_mt5_history` to a noop via `monkeypatch.setattr`. Tests that DO
exercise sync (test_position_id_join, test_fill_origin, ...) build their
own fixture and call `sync_mt5_history` directly, so they are unaffected.

**Important — wrong-fix detour.** I first added a guard in
`sync_mt5_history` that returned early when `self.db_path` was not the
canonical production DB. That broke 4 additional tests that intentionally
exercised `sync_mt5_history` on temp DBs (test_position_id_join et al.),
so I reverted it. Lesson: the test, not production code, should absorb an
environment leak. Committed 775b4eb.

**Final state:** full pytest 3004 pass, 0 fail.
