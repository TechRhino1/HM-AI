### 🔴 Dead branch 1 — the liquidity-sweep penalty never fires

The critic tests `sweep_type == "BUY_SIDE"` / `"SELL_SIDE"`. But `LiquidityContext.sweep_type` is only
ever `"BULLISH_SWEEP"` / `"BEARISH_SWEEP"` / `"NONE"` — documented at `schemas.py:94`, produced solely
by `liquidity.py:108,115` (the only other `LiquidityContext` producer, `dynamic_levels.py:561`, leaves
it at the default). Those two strings exist only in `news.py:720`, for an unrelated post-news
narrative. **A fresh sweep against your trade is never penalised.** Intended mapping would be
BUY → `"BEARISH_SWEEP"`, SELL → `"BULLISH_SWEEP"`.

### 🔴 Dead branch 2 — the cross-asset correlation check never fires

It needs a `"EURUSD"`/`"GBPUSD"` key inside `mtf_alignment`, but `market_context.py:115` only ever
writes timeframe keys. `get_correlation` is still called twice per critique (Python evaluates it before
the `and`) and the result discarded. Note the `pair_sym in mtf` guard is *redundant* — removing it
changes nothing, because `isinstance(mtf.get(pair_sym), str)` already no-ops on a missing key.

### 🔴 The HTF conflict message names the wrong frame

`macro_bias = mtf.get("H4") or mtf.get("D1")` prefers H4 whenever it is truthy, so when D1 is the
frame in conflict and H4 is merely NEUTRAL the threat reads "Macro timeframe is NEUTRAL" — naming a
frame that is not in conflict and hiding the bearish one that triggered it. Penalty (12.0) is correct;
only the explanation is wrong.
